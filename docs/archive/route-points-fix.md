- 출발/도착 안내가 없으면 경로 선형의 양 끝을 사용한다. 경유 안내가 없으면 해당 결과 핀은 생략한다.
- 경유지는 안내의 section_no와 입력 경유지 순서로 대응한다. 가까운 선형 점으로 투영하지 않으므로 순환 경로의 다른 구간을 잘못 선택하지 않는다.
- 입력 좌표, 웹 입력 복원, 이력 저장 좌표는 변경하지 않는다. 이력 조회 시 결과 핀도 갱신하고 기존의 불필요한 핀을 정리한다.
- Python 단위 검사 64개 통과. QGIS 3.44.14/4.2.2에서 결과 핀, 입력 보존, 이력 선택, 안내 누락 대체 검사를 통과했다.
- 실제 SDK 화면의 핀 위치 재확인은 필요하다. Git 커밋/푸시는 이번 수정 범위에 포함하지 않았다.

## 별도 확인: 줌 동작

제공 영상(21.84초)에서 QGIS 휠 줌 중 카카오 지도와 로드뷰 위치가 변경되는 것을 확인했다.
현재 CanvasSyncController는 extentsChanged를 받고, plugin._sync_canvas_center는 새 캔버스 중심을 전달한다.
웹 moveViewer는 지도를 재중심화하고 getNearestPanoId로 로드뷰를 재조회한다.
축척/카카오 확대 단계는 현재 동기화 대상이 아니다.
영상 8.03초와 14.03초의 웹 상태 좌표도 각각 37.473988,127.120894와 37.472800,127.118024로 다르다.
휠 줌의 중심 변경과 로드뷰 재조회가 결합된 동작으로 보이나, 영상만으로 별도의 역방향 피드백까지 확정하지 않는다.
줌 동작 코드는 이번 핀 수정에서 변경하지 않았다. 로드뷰 위치 유지와 화면 중심 추종 중 원하는 정책을 정한 뒤 별도 수정한다.

후속: 사용자가 줌 중 로드뷰 위치 유지 방식을 승인하여 구현했다. 최신 상태와 검증은 [줌 정책](../zoom-roadview-policy.md)을 참조한다.

## 중복 핀 표시 정리

사용자가 양방향 줌 연동 정상 작동을 확인했다. 경로 핀은 같은 좌표에 크기만 다른 핀이 겹쳐 보여,
현재 Kakao Route Guidance 표시 레이어의 start/destination/waypoint 범주만 기본 렌더링을 끈다.
Kakao Route Points의 큰 핀과 직진·회전·유턴 등 다른 안내 범주는 그대로 표시한다.
범주와 안내 피처를 삭제하지 않으므로 안내 선택, 이력 저장·가져오기·내보내기는 유지한다.
독립적으로 조회하는 이력 레이어의 기본 스타일에는 이 숨김 정책을 적용하지 않는다.
현재 경로와 이력 선택 후 재표시 모두 같은 중복 숨김 정책을 사용한다.
