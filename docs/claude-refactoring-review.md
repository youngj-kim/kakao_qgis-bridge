# Claude 정적 검토 재검토 (2026-10-07)

## 범위와 방법

사용자가 전달한 `stage3-import-compatibility-test` ZIP 검토 내용을 현재 작업 코드와 대조했다. 현재 코드는 이후 스타일 및 표시 레이어 분리까지 포함하므로 ZIP과 행 번호는 다르다. 제품 코드는 수정하지 않았다.

실행 확인은 설치된 QGIS 3.44.14 및 4.2.2의 offscreen Python 런타임을 사용했다. 카카오 SDK 화면의 드래그 떨림, 실제 모달 창 중첩, 장시간 브라우저 사용은 이번 확인 범위 밖이다. 확인 스크립트는 `tests/qgis_refactoring_review_probe.py`, `tests/bridge_restart_review_probe.py`다. 이 스크립트는 관찰 결과를 출력하며, 회귀 테스트 통과 수치에 포함하지 않는다.

## 항목별 판단

1. **내장 도크 이동 에코: 수정 대상.** 도크 신호에 출처가 없으며 `_sync_canvas_center()`는 표시된 도크에 항상 `set_center()`를 호출한다. 두 QGIS 런타임에서 `_handle_viewer_moved()` 한 번에 도크 `set_center()` 한 번을 확인했다. 자기 뷰어에 좌표가 돌아가는 것은 확인됐지만 화면 떨림의 정도는 실제 SDK에서 확인해야 한다. 도크 출처와 외부 클라이언트 출처를 구분하고, 원래 보낸 뷰어만 제외하면서 다른 뷰어 동기화는 유지하는 것이 적절하다.

2. **Windows 재시작 포트 바인딩: 이번 시험에서 미재현.** 독점 바인딩과 HTTP/1.0 사용은 실제 코드와 일치한다. 사용 중인 8081/8082는 건드리지 않고 OS가 배정한 임시 포트에서 각각 HTTP 요청 20회 후 서버 종료 및 동일 포트 즉시 재시작을 3회 시험했으며 모두 성공했다. 이는 실제 브라우저의 장시간 폴링/동시 요청/플러그인 리로드 상황 전체를 검증한 것은 아니다. Microsoft 문서도 독점 바인딩한 소켓은 종료 직후 항상 재사용할 수 있는 것은 아니라고 설명한다. 다만 현재 플러그인의 TIME_WAIT 장애가 확정되지는 않는다. HTTP/1.1 전환 시에도 응답 길이, 연결 수명, 서버 종료를 함께 검토해야 한다. 기존 동시 실행 충돌을 막는 독점 바인딩을 단순히 제거하는 방식은 적절하지 않다.

   참고: https://learn.microsoft.com/en-us/windows/win32/winsock/so-exclusiveaddruse

3. **외부 이벤트 예외로 묶음 유실: 수정 대상.** 큰 정수 `10**400`을 이동 경도에 넣은 이벤트 다음에 정상 이동 이벤트를 배치했다. 두 런타임 모두 `OverflowError`가 밖으로 전파되고, 큐는 이미 비워져 뒤쪽 정상 이벤트가 처리되지 않았다. 이벤트별 예외 처리가 필요하다. 현재 `payload` 접근 일부가 try 밖에 있으므로 예외 경계도 함께 정리해야 한다.

   **동일 QTimer의 모달 재진입은 미확정.** 실제 Qt에서 동일 타이머의 콜백 안에 100ms 중첩 이벤트 루프를 실행했지만 두 런타임 모두 최대 콜백 깊이는 1이었다. 따라서 중첩 이벤트 루프만으로 같은 120ms 타이머가 재진입한다고 단정하면 안 된다. 방어용 처리 중 플래그는 가능하지만, 삭제 확인창 중첩이 재현됐다는 의미는 아니다.

4. **가져오기 검증 반복 순회: 개선 대상.** 경로별로 전체 안내를 다시 세고, 이력 ID마다 기존/신규 안내 전체를 다시 훑는다. ID별 그룹을 한 번 만드는 방식은 검증 규칙을 유지하면서 반복 순회를 줄일 수 있다. 기존 세션 전체를 읽고 geometry를 검증하는 비용은 별도로 남는다. 실제 GUI 지연의 크기는 이력 규모별 측정이 필요하다.

5. **전체 스냅샷 비용: 타당하나 최적화 설계 필요.** 추가 작업에서도 기존 feature 전체를 보관하고 WKB와 속성을 비교한다. 그러나 이 코드는 건수뿐 아니라 기존 이력의 변경 여부와 복구 결과도 검증한다. ID/건수 확인만으로 대체하면 같은 보장을 유지하지 못한다. 추가 전용 최적화는 적용할 provider 범위, 부분 성공 처리, 복구 검증을 먼저 정하고 실패 주입 시험을 유지해야 한다.

6. **사용하지 않는 가져오기 경로: 제거 대상.** `append_layer()` → `prepare_layer()` → `append_imported_features()` 연결은 현재 실제 가져오기 UI에서 쓰이지 않는다. 호출자는 사용하지 않는 `_append_imported_history()` 위임 함수뿐이며 테스트 참조도 찾지 못했다. 입력 검증 경로를 우회할 수 있으므로 제거가 합리적이다. 다만 `append_imported_features()` 자체는 `HistoryOperations`를 사용하므로 변경 결과/복구 검사까지 우회한다는 뜻은 아니다.

## 낮은 우선순위 및 배포 사항

- SHP 문자열은 내보내기 준비 시 문자 수로 잘리고 UI 경고가 없다. DBF의 바이트 폭과 한글 입력은 별도 검증하고, 손실 가능성은 내보내기 전에 안내하는 것이 좋다.
- GPX의 금지 제어문자 처리는 실제 문제다. `GpxWriter`로 U+0001을 포함한 이름을 생성하면 표준 XML 파서에서 `ParseError`가 발생했다.
- 빈 입력과 기존 이력 중복을 같은 메시지로 표시하는 문제는 코드와 일치한다.
- `OGC:CRS84`와 `EPSG:4326`의 직접 equality 비교는 두 런타임 모두 false였다. 명시적 CRS84 레이어를 거부할 가능성은 있으나 일반 GeoJSON이 전부 거부된다는 뜻은 아니다. 실제 OGR의 CRS 판정 및 경도/위도 순서를 확인한 뒤 허용 범위를 정해야 한다.
- 저장된 잘못된 REST 키 안내는 사용성 개선 사항이다. 키 형식 검증 자체는 이미 있다.
- POST 본문을 인증 전에 읽는 순서와 URL 쿼리 토큰은 현재 코드에 남아 있다. 인증 선행 변경은 HTTP 연결 처리와 함께 검토하고, 토큰 전달 변경은 별도 설계 항목으로 유지한다.
- 버전/changelog가 1.1.1인 것은 테스트 패키지 단계의 현재 상태다. 정식 릴리스 전에는 구분 가능한 버전 및 변경 기록이 필요하다.
- 최소 QGIS 3.34를 선언하지만 이번 실행 근거는 3.44.14/4.2.2다. 3.34 미검증과 3.34 미지원은 구별해야 한다.
- 작업 폴더 README에는 이미 8081/8082 및 SDK 도메인 등록 안내가 있다. 배포 ZIP의 README 포함 여부와 플러그인 about 안내는 별도로 개선할 수 있다.
- 배포 ZIP에 tests/docs가 없는 것은 실행 검증 부재의 증거가 아니다. 작업 폴더의 테스트/문서로 확인해야 하며, 정적 검토자가 ZIP만으로 통과 수치를 확인하지 못했다는 한계는 타당하다.

## 권장 순서

1. 도크 자기 에코 및 이벤트별 예외 격리.
2. 사용하지 않는 검증 우회 경로 제거 및 가져오기 안내 그룹화.
3. Windows 재시작 시험 결과에 따른 연결 종료/재바인딩 처리.
4. SHP 손실 안내, GPX 제어문자, 빈 파일 메시지.
5. 측정 결과를 바탕으로 추가 전용 이력 변경 최적화.
6. 릴리스 버전/변경 기록, 배포 안내, 최소 지원 버전 확인.
