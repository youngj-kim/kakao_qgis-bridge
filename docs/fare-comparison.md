# 요금 저장·비교 — 1.2.2 개발 후보

카카오·네이버 요금 저장 기능으로 새 경로를 조회해 각각 GPKG로 내보낸 뒤,
카카오 플러그인의 GPKG 비교창에서 두 파일을 선택한다. 통행료와 예상 택시요금을
각각 A/B 금액 및 차액(B−A)으로 표시한다. 양수는 B가 비싸고 음수는 B가 저렴하다.

공통 필드는 `toll_fare`, `taxi_fare`이며 원 단위의 0 이상 정수 또는 NULL이다.
명시적인 0원과 미수집/누락 정보를 구분한다. 어느 쪽이든 요금이 없으면 해당 차액은
비교 불가다. 기존 GPKG에서 요금을 추정하거나 소급 채우지 않는다. 두 플러그인 모두
요금 저장 기능을 설치하고 다시 조회해야 한다. 같은 이력 ID를 기존 파일에 다시 저장하면
기존 중복 방지 정책이 적용되므로 새 파일로 내보내는 것을 권한다.

두 API의 항목은 다음과 같이 원문 금액을 보존한다.

| 저장 필드 | 카카오 | 네이버 |
| --- | --- | --- |
| toll_fare | summary.fare.toll | summary.tollFare |
| taxi_fare | summary.fare.taxi | summary.taxiFare |

출처: [Kakao Mobility 자동차 길찾기](https://developers.kakaomobility.com/guide/navi-api/directions),
[NAVER Directions 5](https://api.ncloud-docs.com/docs/application-maps-directions5).
예상 택시요금과 통행료를 합산하지 않는다. 서비스별 조회 시점·차량·할증 계산 차이가
있을 수 있으므로 같은 산정 기준이나 실제 청구액을 보장하지 않는다.

카카오 이력은 GPKG/GeoJSON/SHP와 GPX 확장에 요금을 저장한다. NAVER는
GPKG/GeoJSON/SHP와 이력 가져오기에 요금을 보존하며 기존 GPX 확장은 변경하지 않는다.
schema_ver=2의 선택 필드 추가이므로 요금 없는 기존 파일도 읽을 수 있다.
카카오 가져오기는 양쪽 이력에 요금이 존재하고 같은 ID의 금액이 다르면 충돌로 거부한다.

## 검증

2026-10-13 사용자가 요금 기능 테스트에 이상 없음을 확인했다. 아래 자동 검증과 별개로 기록하며 모든 QGIS 버전의 확인을 뜻하지 않는다.

- 카카오 Python 81개, JavaScript 49개; 네이버 Python 53개 통과.
- QGIS 3.44.14/4.2.2에서 합성 API → 메모리 이력 → GPKG/GeoJSON/SHP → 비교 UI,
  통행료 +1,200원·택시요금 -500원 차액, NULL/0 구분, 카카오 GPX 확장 및 가져오기 충돌 거부.
- 기존 카카오 이력 가져오기·내보내기·비교와 NAVER 전체 오프라인 스모크 테스트 통과.
- 사용자 카카오·네이버 GPKG 목록·선 읽기, 요금 누락 처리 및 원본 SHA-256 보존 확인.
- 실제 API 키/유료 호출과 지도 화면은 사용하지 않았다. 정확한 QGIS 3.34와 실제 API
  재조회·내보내기·비교 화면 확인은 별도로 필요하다.

승인 대기 중인 1.2.1 패키지는 변경하지 않는다. 이번 카카오 ZIP은 1.2.2 테스트 후보이며,
NAVER ZIP은 기존 0.2.0 메타데이터와 기존 작업 트리 변경을 포함한 테스트용이다.
공식 업로드·태그·커밋·푸시는 별도 요청 전 수행하지 않는다.
