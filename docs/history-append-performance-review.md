# 이력 추가 성능 및 복구 보장 검토

검토일: 2026-10-07. 이 단계에서는 제품 코드와 배포 ZIP을 변경하지 않았다. 임시 QGIS 메모리 레이어 및 테스트에만 최적화 후보를 적용했다.

## 권장 결론

추가 전용 ID/건수 검사로 전환하지 않고, 전체 스냅샷과 기존 geometry·속성 비교 및 보상 복구를 유지한다. 우선 공통 `_key()`의 속성 NULL 판정에서 일반 Python 문자열·숫자·bool에 대한 불필요한 Qt 호출을 줄이는 방식을 적용하는 것이 합리적이다. 별도 추가 전용 변경 경로를 만들지 않아 추가·가져오기·삭제의 보장을 같은 방식으로 유지할 수 있다.

## 현재 비용의 실제 구성

현재 `_features()`는 QgsFeature 복사본을 보관하지만 모든 geometry를 즉시 deep copy하는 것으로 해석하면 안 된다. QgsFeature는 암묵적 공유를 사용한다. [QGIS 3.34 공식 API](https://api.qgis.org/api/3.34/classQgsFeature.html)

실제 측정에서 스냅샷 전후 feature 수집보다 `_key()`의 반복 호출 비용이 컸다. 이 함수는 WKB bytes와 NULL 정규화한 속성 문자열 tuple을 만든다. 같은 ID의 기존 feature가 추가 작업 중 변경됐는지 감지하는 기능도 맡으므로 검사를 삭제하면 보장이 달라진다.

`tests/qgis_history_operations_profile.py`에서 같은 경로 수·안내 수로 각 모드를 교대 3회 실행했다. 경로당 500개 정점, 이력당 안내 4개를 만들고 새 경로 1개·안내 4개를 한 작업으로 추가했다. 모드 간 추가 데이터를 제거해 같은 크기로 시작했다. 각 값은 중앙값이며, 측정용 wrapper 및 mock 호출 비용도 포함한다.

| 환경/기존 데이터 | 현재 `_key` 시간 | 후보 `_key` 시간 | 현재 전체 추가 | 후보 전체 추가 |
| --- | ---: | ---: | ---: | ---: |
| QGIS 3.44.14 / 경로 200·안내 800 | 0.023초 | 0.012초 | 0.036초 | 0.024초 |
| QGIS 3.44.14 / 경로 1,000·안내 4,000 | 0.412초 | 0.303초 | 0.547초 | 0.521초 |
| QGIS 4.2.2 / 경로 200·안내 800 | 0.132초 | 0.050초 | 0.179초 | 0.114초 |
| QGIS 4.2.2 / 경로 1,000·안내 4,000 | 0.784초 | 0.251초 | 1.005초 | 0.485초 |

동시 실행의 초기 시험에서는 후보 전체 시간이 더 느린 경우도 있었다. 표는 두 QGIS 프로세스를 각각 단독으로 실행한 반복 결과다. 전체 시간의 개선폭은 환경에 따라 다르며 QGIS 3의 큰 데이터 시험은 제한적인 개선이었다. 일정한 배수, 실제 사용자 GUI의 시간 또는 모든 이력 크기에 대한 결과를 보장하지 않는다. 이 변경은 기존 전체 순회를 제거하지 않으므로 복잡도 자체는 이력 크기에 계속 비례한다. 파일 가져오기 정규화 비용은 이 측정 범위에 포함하지 않는다.

## 유지해야 할 보장과 배제할 방식

1. **ID/건수만 확인하는 추가 경로는 적용하지 않는다.** 실제 memory provider에 새 feature를 추가하면서 기존 origin_name을 변경하고 성공을 반환하게 했다. 현재 검사는 이를 실패로 감지하고 geometry·속성과 선택을 복원했다. ID/건수만으로는 해당 기존 데이터 변경을 검출할 수 없다.
2. **geometry의 일반 동등성 검사로 WKB를 대체하지 않는다.** 점 경도의 1e-9 차이를 시험했을 때 QGIS 3.44.14의 `equals()`는 true였으나 WKB는 달랐다. QGIS 4.2.2에서는 두 비교가 모두 false였고 equals()는 deprecated였다. 버전과 허용 오차에 따라 결과가 달라질 수 있으므로 현재의 바이너리 비교를 유지한다. [QGIS geometry API](https://api.qgis.org/api/classQgsGeometry.html)
3. **작업 간 fingerprint 캐시를 만들지 않는다.** 레이어/provider의 직접 변경까지 빠짐없이 무효화할 계약이 필요하다. 그 보장이 없는 캐시는 오래된 값을 비교 기준으로 사용할 수 있다.
4. **스냅샷·capability 사전 확인·편집 중 거부·실제 ID/건수 검사·복구 결과 검증을 유지한다.** 복구 실패 시 추가 변경 차단과 내보내기 허용 정책도 유지한다.

## 후보의 구체적인 동작

테스트용 `tests/history_key_candidate.py`:

- None은 None으로 유지한다.
- 정확한 Python 기본형 `str`, `int`, `float`, `bool`은 기존처럼 str(value)로 변환한다.
- 그 밖의 QVariant/날짜/사용자 정의 타입은 기존 QgsVariantUtils.isNull(value)와 str(value) 경로를 사용한다.
- geometry WKB 생성 및 bytes 비교는 바꾸지 않는다.

None/NULL, 빈 문자열, 문자 "NULL", 한글, bool, 정수, 0.0/-0.0, NaN/무한대, 유효·무효 QDate, 무효 QDateTime을 기존 키와 대조했고 두 QGIS에서 일치했다. 실제 provider가 반환한 fixture의 전체 속성 키도 대조했다. 일반 기본형의 하위 타입은 빠른 경로에 포함하지 않는다. QGIS 3.34의 실행 검증은 이번 범위에 포함하지 않았다.

`tests/qgis_history_key_candidate_audit.py`는 후보를 테스트 프로세스의 HistoryOperations에만 주입하여 기존 실패 회귀 검사를 실행한다. QGIS 3.44.14와 4.2.2 모두 다음 항목이 통과했다: 읽기 전용 대상 사전 거부, False/부분 반영/전부 반영 후 False/예외/성공 반환이나 미반영, 개별·전체 삭제의 데이터/선택 복구, 부분 가져오기 복구, 복구 실패 표시 및 후속 쓰기 차단/내보내기 허용, 실패 후 활성 UI 상태와 요청 busy 해제.

## 다음 구현 및 검증 범위

제품 코드에 반영할 때는 HistoryOperations의 속성 키 생성에만 후보를 적용하고 나머지 성공 검사와 복구 경로를 유지한다. 대표값 비교를 실제 적용된 함수에 대한 회귀 검사로 전환한다. 기존 데이터 변조·미세 좌표 변경을 추가 중 감지/복구하는 회귀도 유지한다. 추가/삭제/가져오기 실패 검사 및 정상 이력 UI·파일 호환 검사를 양쪽 QGIS에서 다시 실행한 뒤 별도 테스트 ZIP을 만든다.

## 2026-10-07 — 사용자 승인 후 실제 적용

공통 `HistoryOperations._key`에 위 기본형 처리를 적용했다. 전체 스냅샷, WKB 비교, 성공 판정과 복구 절차는 유지한다. 후보용 helper는 `tests/history_key_reference.py`의 이전 알고리즘으로 전환했고, 후보 주입용 audit wrapper는 제거했다. profile은 이제 baseline(이전 알고리즘)과 optimized(실제 제품 함수)를 대조한다. 위 후보 파일명들은 적용 전 검토 당시의 기록이다.

QGIS 3.44.14/4.2.2 모두 대표 속성 및 실제 provider 값이 이전 알고리즘과 일치했다. 실제 제품 함수를 사용한 failure audit 17개 관찰 항목, 정상 history smoke 및 history validation이 양쪽에서 통과했다. 기존 속성 변조와 경도 1e-9 변경을 추가 도중 주입하고, 독립적인 이전 키로 원본 내용과 선택 상태의 복구를 확인하는 검사를 추가했다.

적용 후 동일 fixture의 3회 중앙값(초):

| QGIS | 기존 경로/안내 건수 | 전체 추가 검사 baseline | optimized |
| --- | --- | --- | --- |
| 3.44.14 | 200/800 | 0.03799 | 0.02557 |
| 3.44.14 | 1000/4000 | 0.23922 | 0.47750 |
| 4.2.2 | 200/800 | 0.19932 | 0.10531 |
| 4.2.2 | 1000/4000 | 1.08995 | 0.50138 |

이전 검토 측정과 달리 이번 QGIS 3 대규모 fixture에서는 optimized가 느렸다. 계측 자체의 비용과 실행 편차가 있으므로 일관된 성능 개선이나 특정 배율을 보장하지 않는다. 이 변경은 기본형의 불필요한 Qt 호출을 줄이며, 전체 이력을 순회하는 복잡도는 그대로다. 속도 보장보다는 비교 의미와 복구 보존이 이번 적용의 검증 기준이다. 최소 QGIS 3.34 및 실제 사용자 GUI 동작 검증은 이 실행 결과에 포함하지 않는다.
