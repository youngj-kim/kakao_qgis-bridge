# 외부 이력 파일 입력 검증 정책 검토

검토일: 2026-10-07. 현재 `HistoryImportService`, 공통 필드 매핑, 내보내기 서비스, README와 배포 ZIP 1.1.0·1.1.1의 이력 스키마를 정적으로 확인했다. 이 단계는 검토이며 실행 코드·ZIP을 변경하지 않는다.

## 결론

파일 전체를 먼저 읽어 좌표·ID·경로/안내 연결을 검증한 뒤, 정상일 때만 저장소의 checked 변경 경로를 호출하는 방식을 권장한다. 검증 실패 시 이번 불러오기 데이터는 추가하지 않는다. 잘못된 행을 조용히 버리고 완전한 이력처럼 완료 안내를 표시하지 않는다.

위험한 좌표·식별자·연결 문제와 형식상 정보 손실을 구분해야 한다. 자체 SHP는 긴 문자열과 경유지 JSON이 잘릴 수 있고 기존 GPKG의 새 필드는 NULL일 수 있다. 이 경우까지 모두 엄격하게 거부하면 현재 정상 파일 호환성을 깨뜨린다.

## 현재 확인 사항

- 현재 geometry는 EPSG:4326 대상에 변환 없이 복사된다. CRS·geometry 종류·좌표 범위 검증은 없다.
- schema_ver 값은 복사하지만 지원 버전 판정이나 필수 필드 검증은 없다. 1.1.0과 1.1.1 ZIP은 모두 schema 버전 2다. 실제 버전 1 샘플은 이번 검토에서 확보하지 않았다.
- README에는 기존 GPKG에 필드를 추가해도 기존 행의 새 필드는 NULL로 유지된다고 되어 있다. 컬럼 존재만으로 값이 유효하다고 가정할 수 없다.
- SHP의 waypoints_json/waypts는 254자 제한이다. README도 SHP의 정보 손실을 명시한다. JSON 파싱 실패를 무조건 파일 손상으로 판단하면 플러그인 자체 출력을 거부할 수 있다.
- 경로와 안내는 각각 대상의 history_id로 건너뛴다. 파일 내부의 경로 ID 중복, 같은 ID의 다른 내용, 고아 안내나 sequence 충돌은 판정하지 않는다.

## 권장 정책

### CRS와 geometry

첫 구현에서는 **유효한 WGS84/EPSG:4326만 허용**하고 다른 CRS·알 수 없는 CRS는 명확한 오류로 거부한다. CRS 비교는 문자열 authid만 보지 않고 QGIS의 좌표계 동등성도 확인한다. GeoJSON의 OGR 해석과 기존 자체 출력을 QGIS 3·4에서 기준으로 고정한다.

다른 CRS를 자동 변환하지 않는다. geometry뿐 아니라 출발·도착 좌표, 안내 좌표, 경유지 JSON 좌표가 어떤 CRS인지 알아야 제대로 변환할 수 있기 때문이다. 오류에서는 원본 CRS와 허용 CRS를 알려 주고 기존 데이터를 유지한다.

- 경로: 비어 있지 않은 2차원 선과 최소 두 점. SHP가 한 부분짜리 MultiLineString으로 읽히는 경우는 정상 호환 대상으로 단일 선으로 정규화한다. 실제 여러 부분인 선, 곡선·면·점 등 다른 종류는 거부한다. 여러 부분에서 첫 부분만 가져오지 않는다.
- 안내: 비어 있지 않은 단일 점. 다른 geometry 종류는 거부한다.
- 모든 geometry와 속성 좌표: 유한한 숫자, 경도 -180~180·위도 -90~90. 잘못된 값을 0으로 대체하지 않는다.
- 안내 속성 longitude/latitude와 점 geometry: 내보내기 좌표 반올림을 고려한 허용 오차 내에서 일치해야 한다. 초기 기준은 1e-7도이며 실제 자체 GeoJSON/SHP/GPKG 결과로 확인한다.
- 출발·도착 요청 좌표와 경로 geometry 끝점은 반드시 일치시키지 않는다. 요청 위치와 도로에 맞춘 경로 위치가 다를 수 있다.

### 스키마와 필드

현재 버전 2의 자체 출력은 유지한다. schema_ver/schema_v가 없거나 NULL이면 레거시 후보로 분류해 아래 필수 데이터를 확인하고 경고와 함께 복원한다. 버전 1은 실제 샘플을 확보하기 전 완전 호환을 선언하지 않으며 동일한 필드 구조에 대한 호환 후보로만 검사한다. 지원하지 않는 미래 버전, 0·음수·비정수 버전 값은 거부한다.

경로 필수 데이터는 history_id, 선 geometry, 유효한 출발/도착 좌표다. 안내가 한 건 이상이면 각 안내에 history_id, 유효한 sequence, 점 geometry와 안내 좌표가 필요하다. 어느 레이어에서든 하나의 필수 필드가 누락되거나 필수 값이 NULL이면 원본 레이어·행·필드 정보를 포함한 오류로 거부한다. 출발/도착 좌표를 geometry 끝점으로 임의 생성하지 않는다.

이름·검색 시각·설명·경로 ID·차량/회피 옵션 등 선택 필드는 알려진 레거시 기본값 또는 빈 값으로 복원하고 무엇이 없었는지 경고한다. 현재 지도·입력 복원의 기본값과 맞춰야 한다. 레거시를 현재 버전으로 정규화해 저장할 경우 원본에서 새 속성을 완전히 복원한 것처럼 안내하지 않는다.

전체 필드명과 SHP 짧은 필드명은 공통 매핑을 사용한다. 둘 다 있고 값이 서로 다르면 필수/연결 필드는 거부한다. 선택 필드는 기존 전체 이름 우선 정책을 유지하면서 차이를 경고한다. 문자열 ID는 공백만 있는 값과 저장 길이를 넘는 값을 거부하며 UUID 형식을 강제하지 않는다. 현재 테스트·레거시의 h1 같은 ID도 유효하다.

안내가 없는 정상 경로는 허용한다. 빈 안내 GeoJSON에는 feature 속성 필드가 없을 수 있으므로 0건 레이어에 비어 있는 행의 필수 필드 검사를 요구하지 않는다. 파일 자체가 없는 것과 유효한 빈 안내 레이어를 구분한다.

### 숫자·경유지 JSON

제공된 거리·시간·안내 건수·sequence는 불리언이나 소수 절삭으로 정수 처리하지 않는다. 정수 또는 정수 표현 문자열만 허용하며 거리·시간·건수는 0 이상, sequence는 1 이상으로 검사한다. 없는 레거시 선택 값과 잘못된 제공 값을 구분한다. 레거시 안내 건수는 실제 연결 안내에서 산출하고 그 사실을 경고한다.

경유지 JSON은 list이며 각 항목의 좌표와 필요한 자료형을 검사한다. 허용 개수는 현재 MAX_ROUTE_WAYPOINTS와 동일하게 유지한다.

- GPKG/GeoJSON: 유효하지 않은 JSON·구조·좌표는 파일 오류로 거부한다.
- SHP: 잘려 파싱되지 않는 경유지 JSON은 경고와 함께 입력창 복원용 경유지를 비운다. 이를 복원 성공으로 안내하지 않는다. 정상 JSON의 잘못된 좌표는 형식 제한 때문이라고 가정하지 않고 거부한다.

SHP에서 손실된 긴 이름·설명·JSON을 기존 세션의 완전한 값 위에 덮어쓰지 않는다. 옵션 값 검증은 현재 경로 요청에서 허용하는 값과 일치시켜 입력창으로 복원된 값을 재요청할 수 있게 한다.

### 배치 내부 중복과 안내 연결

경로는 history_id당 한 건, 안내는 `(history_id, sequence)`당 한 건을 기준으로 한다. 같은 history_id의 여러 안내는 정상이며 history_id만으로 안내를 한 건으로 줄이지 않는다.

- 파일 내부에서 식별자가 같고 정규화된 내용도 같은 행은 중복으로 제거하고 건수를 알려 준다.
- 같은 식별자에 다른 경로·안내 내용이 있으면 파일 전체를 거부한다. 임의로 첫 행/마지막 행을 선택하지 않는다.
- 안내의 history_id는 파일의 경로 또는 이미 존재하는 동일한 경로와 연결돼야 한다. 연결할 경로 없는 안내는 거부한다.
- route_id가 양쪽에 제공돼 있으면 연결된 경로와 안내에서 일치해야 한다. 레거시에서 빠진 선택 경로 ID와 불일치 값을 구분한다.
- 제공된 guidance_count는 중복 제거 후 해당 경로의 안내 건수와 일치해야 한다. 일치하지 않으면 누락·충돌로 거부한다. sequence는 양의 정수와 고유성을 요구하되 미확인 레거시에서 항상 1..N 연속이라고 가정하지 않는다.

### 기존 세션과 같은 ID

기본은 **기존 데이터를 덮어쓰지 않는 병합**이다. 동일한 경로로 확인된 이미 존재하는 ID는 건너뛰고, 다른 경로이면 충돌 오류로 파일을 거부한다. 동일 ID라는 이유만으로 다른 내용을 조용히 무시하지 않는다.

동일 경로 판단은 geometry·출발/도착 좌표·제공된 route_id·거리/시간 등의 핵심 값을 기준으로 한다. geometry 반올림은 허용 오차를 사용하고 레거시 미제공 값은 비교 불가로 구분한다. SHP가 잘라낸 선택 문자열과 옵션은 보조 차이로 경고하며 완전한 기존 값을 유지한다. 비교 기준과 경고가 정상 세 형식의 재불러오기를 거부하지 않는지 먼저 검증한다.

기존 안내가 전혀 없을 때 현재 코드가 안내를 보충할 수 있는 동작은 보존한다. 다만 동일 경로 확인과 파일의 완전한 연결 안내 검증을 통과한 경우에만 보충한다. 기존 안내가 일부만 있고 파일 내용이 다르거나 누락 sequence가 있는 경우는 자동 부분 수리하지 않고 충돌/불완전 안내 오류로 알린다. 기존 안내 전체가 같으면 재불러오기 중복으로 건너뛴다. 자동 덮어쓰기·부분 복구 선택 UI는 후속 기능이다.

## 반환과 안내

검증 결과에는 추가 예정/실제 추가한 경로·안내 건수, 건너뛴 기존 이력, 제거한 파일 내부 중복, 레거시·SHP 손실 경고를 분리한다. 현재 두 개 건수 tuple을 보고서 모델로 바꿀 경우 플러그인 호출부와 QGIS 스모크를 함께 갱신한다.

경고가 있으면 완료 건수와 함께 경고 요약을 보여 주고 자세한 항목은 로그/상세 메시지로 제공한다. 오류는 해당 파일·레이어·행·history_id·필드와 이유를 알려 준다. 미리검증과 변경 적용을 구분해 저장소의 기존 보상 복구 기능과 중복된 임의 롤백을 import 서비스에 만들지 않는다.

## 권장 구현 순서와 검증

1. QGIS와 무관한 필드·값·ID 규칙과 import 결과 모델을 먼저 정의한다.
2. QGIS 레이어의 CRS·geometry 검증과 두 레이어의 전체 입력 준비를 연결한다.
3. 배치 중복·경로/안내 연결·기존 세션 충돌 검증을 추가하고 검증 후에만 저장소를 호출한다.
4. 정상 GPKG/GeoJSON/SHP·빈 안내·레거시 NULL·SHP 잘린 JSON을 기준으로 QGIS 3·4에서 호환성을 검증한다.
5. 다른 CRS·미상 CRS·잘못된 geometry/좌표·미래 schema·누락 필수 필드·ID/sequence 충돌·고아 안내·건수 불일치를 실제 fixture로 확인한다. 오류 전후 데이터·선택·활성 이력이 동일해야 한다.
6. 기존 실패·복구, 내보내기·이력·범례·브리지 검증 후 테스트 ZIP을 만든다.

이번 단계에서는 해당 불량 파일을 런타임으로 재현하지 않았다. 기존 정상 파일과 provider 실패 검증 결과를 기반으로 한 정책 검토이며, 새 입력 정책의 런타임 검증은 다음 구현 단계에 수행한다.

## 실제 기존 파일로 확인한 정책 보완

구현 후 사용자 보고로 소수점 5자리 속성 반올림, road_index -1, 예전 안내 SHP의 필드 구조를 추가 확인했다. 기존 파일 11개를 양쪽 QGIS에서 검사했고, 제한적인 반올림 호환 및 짝 경로의 유일한 route_id에 의한 예전 안내 ID 복원을 추가했다. 최초 검토의 1e-7 일치/필수 history_id 규칙에 대한 이 좁은 호환 예외와 검증 결과는 `saved-history-compatibility-audit.md`에 기록했다. 일반적인 잘못된 좌표나 모호한 연결을 자동 복구하는 정책은 아니다.
