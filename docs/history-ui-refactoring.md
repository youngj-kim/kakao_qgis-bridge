# 이력 UI 컨트롤러 분리 — 2026-10-08

## 범위

`HistoryUiController`가 이력 목록 payload 작성, 경로·안내 선택,
입력 복원 요청, 개별/전체 삭제 확인 및 저장소 변경을 담당한다.
저장소와 iface를 명시적으로 받으며 플러그인 객체를 직접 받지 않는다.
`HistoryUiCallbacks`는 프로젝트 세대/활성 ID 조회, 표시/입력 전달,
현재 표시 정리, 목록/액션 갱신, 오류 안내의 경계를 정의한다.

지도 표시와 도크·외부 브리지 전송은 플러그인의 표시 어댑터에 유지한다.
메뉴·WebChannel·외부 브리지의 기존 진입점은 얇은 위임 함수로 유지한다.
삭제 확인창 도중 프로젝트가 바뀌면 변경을 취소하며, 저장소 실패 시
성공 메시지나 후속 UI 갱신을 실행하지 않는다.

## 검증

- 변경 전후 QGIS 3.44.14 / 4.2.2 이력 스모크 통과.
- 양 런타임에서 목록 정렬·선택·삭제 취소·활성/비활성/전체 삭제,
  파일 가져오기·중복 병합·입력 데이터 복원 통과.
- 추가 검사: 도크와 외부 브리지에 입력 복원 전달, 없는 ID 무시,
  삭제 실패 시 데이터 유지 및 성공 메시지 미표시.
- 양 런타임에서 프로젝트 clear/read 경계 및 확인창 중 전환 보호 통과.
- 양 런타임에서 카카오·네이버 GPKG 비교와 원본 보존 검사 통과.
- 일반 Python 61개, JavaScript 13개 및 뷰어/브리지 구문 검사 통과.

QGIS 검사는 임시 fixture와 모의 대화상자를 사용하는 별도 offscreen
프로세스다. 실제 설치된 플러그인과 사용자 프로젝트는 변경하지 않았다.
실제 카카오 SDK 화면의 사용자 조작은 새 테스트 ZIP에서 별도 확인한다.
