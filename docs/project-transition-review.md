# 프로젝트 전환 검토 — 2026-10-08

## 실행 근거

`tests/qgis_project_transition_review_probe.py`로 Windows QGIS 3.44.14와 4.2.2의 실제 clear/read를 관찰했다. 임시 빈 프로젝트와 메모리 레이어만 사용했다. 응답은 QObject fixture로 제공하고 실제 MobilityClient 완료 처리와 Qt 성공 신호를 실행했다. 사용자 앱·프로젝트·설치 플러그인과 실제 카카오 API는 사용하지 않았다. 관찰은 회귀 통과 수치나 실제 네트워크/SDK 화면 검증과 구별한다.

## 현재 동작과 원인

두 버전의 clear/read에서 표시 레이어 객체는 삭제되지만 내부 이력 1건, 활성 이력 ID, Python 경로 안내와 외부 스냅샷은 유지됐다. 진행 중 reply도 취소되지 않았다. 전환 후 이전 reply를 완료 처리하면 새 프로젝트에 경로 레이어가 생성되고 이력이 추가됐다.

plugin에는 프로젝트 전환에 대응하는 상태 초기화가 없다. 표시 manager는 삭제된 객체를 다음 조작에서 재생성한다. 내부 이력은 프로젝트에 등록되지 않은 저장소 소유 메모리여서 clear 대상이 아니다. MobilityClient.cancel은 새 요청/unload 때 호출되며 프로젝트 전환에는 호출되지 않는다. 이미 참조 해제·finished 해제·abort·deleteLater와 reply identity 검사 기능은 있다.

## 권장 정책

1. 이력은 플러그인 세션 범위로 유지한다. 프로젝트 전환만으로 저장소를 clear하거나 복구 차단 상태를 해제하지 않는다. 사용자가 이력 탭에서 선택하면 새 프로젝트에 다시 표시한다.
2. 활성 ID, 현재 경로·안내·핀, 이전 성공 상태와 표시 참조/feature ID를 초기화한다. 웹 경로도 비우고 이력 목록은 선택 없이 유지한다. 새 프로젝트의 일반 레이어·GPX·같은 이름 레이어는 제거하지 않는다.
3. 전환 전 요청은 기존 cancel로 취소하고 busy 상태를 해제한다. 전달 대기 중인 완료가 새 프로젝트를 변경하지 않도록 요청/프로젝트 세대 경계도 검토한다. 취소를 경로 성공으로 표시하지 않는다.
4. 전환 전 외부 입력 큐와 이미 drain한 배치도 새 프로젝트에 적용하지 않는다. 모달 도중 전환을 포함하며, 현재 경로·선택·status 스냅샷을 초기화한 뒤 새 입력을 허용한다.
5. 개별 표시 레이어 삭제는 프로젝트 전환과 구분한다. 하나의 레이어 삭제로 전체 상태를 초기화하지 않고 기존 lazy 재생성을 유지한다. 이름만으로 소유권을 판단하지 않는다.
6. 실제 프로젝트 신호 타이밍을 확인하여 연결하고 반복 clear/read와 unload에서 중복 콜백을 방지한다. 새 캔버스 범위가 유효해진 뒤 중심을 동기화한다.

자동 이력 폐기/프로젝트별 분리, 자동 저장과 표시 provider 실패 복구는 별도 범위다.

## 다음 구현·검증

프로젝트 경계 연결, 요청 취소, 표시/활성/웹 초기화를 먼저 구현한다. 늦은 응답과 외부 배치 경계를 함께 정의한다. 실제 clear/read에서 이력·복구 차단 보존, 빈 웹 경로, 취소·늦은 응답 무시, 다음 요청 정상 처리, 모달/큐 차단, 사용자 레이어 보존, 개별 삭제 재생성, 반복 전환/unload를 검증한다. 기존 저장/가져오기·내보내기·브리지·표시/스타일도 회귀 검사한다.

이번 단계는 관찰 스크립트와 검토 문서만 추가했다. 제품 코드·1.2.0 ZIP·GitHub 상태는 변경하지 않았다.

## 후속 구현 — 2026-10-08

사용자 진행 승인 후 aboutToBeCleared/cleared 경계를 연결했다. 전환 시작에서 프로젝트 세대를 증가시키고 현재 요청을 취소한다. 결과는 현재 요청 객체와 세대가 일치할 때만 수신한다. 전환 완료에서 표시 참조·활성 ID·선택을 초기화하고 이력 저장소와 needs_recovery는 유지한다. 새 프로젝트의 캔버스는 지연 동기화한다. 개별 표시 레이어 삭제의 동작은 유지한다.

외부 브리지는 전환 중 입력을 받지 않으며 큐를 비우고 이미 drain한 배치는 세대 변경 시 중단한다. 복사 중 전환된 이벤트도 거부한다. 이전 center·transient 명령·outbound 기록을 초기화하고 현재 상태에 projectReset을 포함해 뒤처진 탭과 새 탭을 복원한다. 브라우저 입력 초기화는 QGIS 핀 삭제 명령을 되돌려 보내지 않으며 같은 세대의 스냅샷 재적용 때 반복하지 않는다.

이력 삭제 확인·파일 선택·REST 키 입력 도중 전환을 검사하며 경로 결과의 저장 오류 대화상자 뒤에서도 이전 표시를 다시 적용하지 않는다. unload에서는 프로젝트 신호를 해제한다. 이미 전환 뒤에 도착한 새 사용자 명령까지 구별하는 브라우저 POST 세대 프로토콜은 이번 변경에 포함하지 않는다. 실제 HTTP 전달 중인 요청 전체를 취소했다고 주장하지 않으며 서버 큐와 처리 중인 GUI 배치를 경계로 삼는다.

QGIS 3.44.14/4.2.2의 신규 project transition smoke에서 실제 clear/read, fixture reply 취소·늦은 완료 무시·새 요청, 이력/복구 차단/선택 정책, 전환 중 입력 거부, 빈 안내/선택 없는 목록, 같은 이름 사용자 레이어, 개별 삭제 재생성, 확인창/파일 선택 도중 전환, unload 후 콜백 해제를 확인했다. Python 단위 61개와 JavaScript 13개 검사가 통과했다. 실제 카카오 SDK 화면의 프로젝트 전환 확인은 자동 처리/스냅샷 검사와 구별한다.
