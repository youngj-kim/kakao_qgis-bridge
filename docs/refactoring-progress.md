# 리팩터링 진행 기록

## 2026-10-07 — 1단계 안정성 수정

[검토안](refactoring-review-1.1.1.md)의 첫 번째 변경 단위를 적용했다. 검토안은 당시 소스에 대한 기록이며, 이 문서는 이후 변경 결과를 기록한다.

### 적용 내용

- REST 키 저장 시와 네트워크 요청 직전에 같은 검증을 적용한다. 앞뒤 공백은 정리하고 빈 값·내부 공백·제어 문자·비ASCII 문자는 거부한다. 키 값을 오류 메시지에 포함하지 않는다.
- 잘못된 REST 키는 Qt `failed` 신호로 전달해 진행 상태를 해제하고 요청을 보내지 않는다.
- 외부 브리지 인증은 ASCII 바이트로 비교한다. 비ASCII URL·헤더 토큰은 예외 대신 HTTP 403으로 거부한다.
- 요청 JSON 필드와 회피 옵션 요소를 검증하고 잘못된 형식을 `RouteValidationError`로 전달한다.
- 응답의 객체·배열 구조와 거리·시간을 검증하고 잘못된 필수 선형은 `MobilityResponseError`로 전달한다. 잘못된 좌표를 제거한 뒤 나머지 지점을 연결해 임의의 경로를 만들지 않는다.
- 선택적인 안내 항목이 손상된 경우 해당 항목을 건너뛰고 정상 경로는 유지한다. 거리·시간이 누락된 기존 응답의 0 기본값은 유지한다.
- HTTP 오류 응답이 객체가 아니어도 실패 신호를 전달하고 401·403·429 메시지를 구분한다.
- 공식 안내 코드 매핑을 명시하고 타입을 문구보다 우선한다. 기존 좌우 입출구·회전교차로 아이콘 정책은 유지한다. 미분류 타입에서 좌우 문구가 함께 나오면 `other`로 표시한다.
- 내장 뷰어 사용 불가 안내는 실제 WebEngine/WebChannel 가용성을 설명하고 import 실패 상세를 함께 제공한다.
- 뷰어의 영어 상태·오류 메시지를 한국어로 맞췄다. 다국어 번역 시스템은 별도 작업이다.

## 2026-10-07 — 2단계 동기화와 외부 브리지 상태 복구

### 적용 내용

- 600ms 역방향 가드를 제거했다. QGIS에 적용한 중심 좌표와 CRS를 저장하고, 현재 중심이 해당 좌표의 0.25픽셀 오차 범위에 있을 때만 반영 신호를 억제한다. 다른 사용자 이동은 즉시 기존 350ms debounce 대상이 되며, CRS 변경·동기화 해제 시 비교 기준을 초기화한다.
- 역방향 이동 후 QGIS의 실제 중심을 다른 뷰어에도 전달한다. 외부 탭은 각자 클라이언트 식별자를 사용하며 자기 이동 이벤트는 다시 적용하지 않는다. 중심과 경로 상태는 공통 이벤트 sequence를 사용한다.
- 외부 서버가 시작되기 전에 활성 경로·안내와 선택 이력 상태를 채운다. 이미 경로를 생성한 뒤 외부 뷰어를 열어도 현재 결과를 복원한다.
- `/api/state`는 중심과 최신 안내·이력·경로 상태 및 기준 sequence를 한 잠금 범위에서 반환한다. 새 탭은 이 스냅샷으로 시작하고 기준 이후 이벤트만 처리한다. 과거 `loadRouteHistoryInput` 명령은 새 탭에 재생하지 않는다.
- 이벤트가 잘려 cursor가 보존 범위를 벗어나거나 서버 기준보다 앞서면 `/api/events`가 현재 스냅샷과 `resync_required`를 반환한다. 클라이언트는 최신 화면 상태로 복구한다.
- 400ms 이중 폴링을 하나의 순차 폴링으로 바꿨다. 초기 스냅샷 이후에는 이벤트만 조회하고, 응답 완료 후 다음 요청을 예약한다. 요청에는 10초 제한을 두고 실패 시 최대 5초까지 재시도 간격을 늘린다.
- POST 실패를 확인해 사용자에게 표시하며 경로 요청 실패는 진행 상태를 해제한다. 삭제·내보내기 같은 명령은 자동 재전송하지 않는다.
- 송신 이벤트 기록은 최대 100개·4MiB로 제한한다. 수신 대기열도 최대 256개·1MiB로 제한하고 초과하면 HTTP 503을 반환한다. 중심·Roadview 갱신은 클라이언트별로 최신 값으로 병합하되 명령 앞뒤의 순서는 보존한다.
- SDK 준비 전에 받은 경로는 최신 payload를 보관한 뒤 지도 초기화 후 다시 그린다. 스냅샷 적용 시 경로 표시 후 중심을 적용해 경로 범위 맞춤이 복원 중심을 덮어쓰지 않도록 한다.
- 도크를 닫더라도 외부 서버가 활성화되어 있으면 캔버스 동기화를 유지한다.

## 2026-10-07 — 지도 드래그 후 로드뷰 미갱신 수정

사용자가 카카오 지도를 이동해도 로드뷰가 바뀌지 않는 증상을 보고했다. `syncKakaoMapToQgis()`는 QGIS 중심만 전달하고 로드뷰 갱신은 QGIS에서 돌아오는 중심 호출에 의존했다. 자기 이동 이벤트를 다시 적용하지 않는 외부 탭에서는 이 경로가 작동하지 않는다.

지도 `dragend`에서 현재 중심의 주변 로드뷰를 직접 조회하도록 수정했다. 드래그 중에는 기존처럼 중심을 QGIS에 전달하고, 드래그가 끝날 때 로드뷰를 갱신한다. 공통 `updateRoadviewPosition()`을 사용해 QGIS에서의 이동과 동일한 로드뷰 처리·오래된 비동기 응답 무시를 유지하며, 드래그 중 지도를 재중앙화하지 않는다. 근처 80m 이내에 촬영 지점이 없으면 기존 안내 문구를 표시한다.

뷰어 회귀 테스트 6개를 추가했다. 지도 드래그 종료, QGIS 연결 준비 전 로드뷰 갱신, 드래그 중 요청 제한, 이전 응답 무시, 촬영 지점 없음, QGIS 이동의 기존 동작을 확인한다. 외부 브리지 테스트와 합쳐 JS 테스트 11개 및 두 스크립트의 구문 검사가 통과했다. 실제 카카오 SDK 화면에서의 확인은 수정본 적용 후 남아 있다.

수동 검증용 `dist/kakao_qgis_bridge-stage2-test.zip`을 생성했다. 메타데이터 버전은 1.1.1이고 기존 버전별 배포 ZIP은 유지한다. 이 테스트 ZIP에는 앞선 1·2단계 수정도 포함한다. 설치 후 QGIS를 다시 시작하고 기존 외부 탭을 닫은 뒤 플러그인에서 새 뷰어를 열어야 최신 Python 서버와 HTML을 함께 사용한다.

## 2026-10-07 — QGIS 3·4 동시 외부 연동의 포트 충돌 수정

사용자가 QGIS 4에서 기능이 정상 작동한다고 확인했다. QGIS 3·4를 동시에 실행하고 QGIS 3 버튼으로 외부 뷰어를 새로 열었을 때에는 HTTP 403 화면이 나타났다. 확인 당시 localhost:8081은 QGIS 4.2.2 프로세스가 사용 중이었다.

Windows의 기본 `ThreadingHTTPServer`는 `SO_REUSEADDR`를 사용해 두 서버가 같은 주소·포트에 bind하는 것을 허용했다. 임시 포트에서 동일 주소에 두 서버를 생성하는 동작을 재현했다. 이 상황에서는 요청이 다른 세션의 서버로 들어가 토큰 불일치로 거부될 수 있다.

Windows에서는 `SO_EXCLUSIVEADDRUSE`를 적용하고 주소 재사용을 비활성화해 두 번째 브리지가 포트를 중복 사용하지 못하게 했다. 기존의 주소 재사용 서버가 먼저 실행 중이어도 새 브리지의 중복 bind를 거부한다. 실패 시 브라우저를 열지 않고 다른 QGIS의 외부 서버가 포트를 사용 중인지 확인하라는 안내를 표시한다. 다른 플랫폼은 기존 주소 재사용 정책을 유지한다.

QGIS 3·4 자체의 동시 실행은 가능하다. QGIS 4 내장 도크와 QGIS 3 외부 뷰어를 함께 사용하는 구성도 가능하지만, 현재 고정 8081 포트의 외부 서버는 한 프로세스만 사용할 수 있다. 이미 외부 서버를 시작한 QGIS 4는 브라우저 탭을 닫는 것만으로 포트를 해제하지 않는다. 두 프로세스의 외부 연동을 모두 사용하는 포트 분리 설정은 아직 구현하지 않았다.

사용자가 QGIS 3·4를 각각 실행할 때에는 이상이 없다고 추가 확인했다. 개별 환경의 기능 검증은 사용자 확인 기준으로 통과했고, 동시 외부 서버 실행의 포트 충돌을 별도 문제로 분류한다. 중복 bind 거부 회귀 테스트를 포함한 외부 브리지 Python 테스트 17개와 수정 Python 파일 컴파일이 통과했다. 테스트 ZIP에 포트 충돌 차단 변경을 반영했다.

## 2026-10-07 — 동시 외부 연동을 위한 자동 포트 분리

사용자 요청에 따라 앞선 충돌 차단에 자동 포트 선택을 추가했다. 플러그인은 8081을 먼저 시도하고 사용 중이면 8082를 사용한다. QGIS 버전과 무관하게 먼저 시작한 외부 서버가 8081을 사용한다. 두 포트 모두 사용 중이면 안내하고 브라우저를 열지 않는다. Windows의 독점 bind와 각 서버의 세션 토큰은 유지한다. 일반 서버 클래스는 명시된 fallback_ports만 시도하며, 관련 없는 I/O 오류는 다른 포트로 숨기지 않는다.

뷰어 URL과 Origin 검증은 실제 바인딩된 포트를 사용한다. 플러그인 안내에 토큰 없는 실제 접속 주소와 SDK 도메인 등록 절차를 표시했다. 기존 JavaScript 키의 `[플랫폼 키] > [JavaScript 키] > [JavaScript SDK 도메인]`에 `http://localhost:8081`과 `http://localhost:8082`를 등록해야 한다. 제품 링크 관리의 웹 도메인 목록은 별도 설정이다. 키 재발급은 필요하지 않다.

Python 테스트 50개, JS 동작 테스트 11개, Python 소스 11개 컴파일 및 뷰어·브리지 JS 구문 검사가 통과했다. 두 HTTP 서버의 다른 포트 선택, 서로 다른 토큰, 다른 서버 토큰 거부, 이벤트 격리, 두 후보 포트 점유, 관련 없는 오류의 전파를 확인했다. QGIS 3.44.14와 4.2.2 런타임에서도 사용 중인 포트를 피한 두 번째 서버의 인증된 HTML 응답과 기존 동기화·스냅샷 기능을 확인했다. 실제 두 QGIS GUI에서의 카카오 SDK 동시 렌더링은 SDK 도메인 등록과 새 패키지 설치 후 사용자 확인이 필요하다.

### 구현

`history_operations.py`에 `HistoryOperations`와 `HistoryOperationError`를 추가했다. 경로·안내 양쪽의 레이어 유효성·provider·추가/삭제 capability와 편집 버퍼 상태를 먼저 확인한다. 필요한 변경과 역작업을 수행할 수 없는 대상이나 현재 편집 중인 이력 레이어는 데이터 변경 전에 거부한다. 요청할 데이터가 없는 레이어는 해당 작업의 사전 확인에서 제외한다.

`HistoryRepository.append`는 경로·안내를 모두 준비한 뒤 한 작업으로 반영한다. 파일 가져오기도 두 원본을 읽고 두 feature 목록을 준비한 뒤 같은 저장소 적용 경로를 사용한다. 실패에 준비한 건수를 완료 건수로 반환하지 않는다. 개별·전체 삭제는 같은 checked 변경·복구를 사용한다.

복구 성공 여부를 오류에 구분한다. 복구가 완료되지 않으면 저장소의 후속 이력 변경을 차단한다. 보관용 내보내기는 계속 가능하며 참조 해제 후 새 세션은 정상 저장소를 사용한다. 두 레이어에 대한 DB 트랜잭션이나 모든 provider에서의 완전한 원자성을 보장하지 않는다. 복구 snapshot은 전체 이력 데이터를 메모리에 복사하므로 이력이 커지면 작업 비용이 늘어난다.

플러그인은 실패에 성공 안내를 표시하지 않고 목록·Action을 실제 상태로 갱신한다. 복구 실패 안내에는 실제 남은 경로·안내 건수를 표시한다. 활성 이력이 없어졌거나 안내 연결이 깨졌으면 해당 현재 표시를 정리하며, 복구된 상태나 영향 없는 활성 이력은 유지한다. 레이어 갱신 자체에서 RuntimeError가 발생해도 원래 실패 안내가 가려지지 않도록 한다.

경로 계산은 성공했지만 이력 저장만 실패하면 계산한 경로·안내를 표시하고 저장되지 않은 history_id는 활성 이력으로 설정하지 않는다. 뷰어에는 이력 저장 실패 상태를 전달해 대기 상태를 해제하고 성공 메시지를 대신하지 않는다.

## 2026-10-07 — 외부 이력 입력 검증 구현

사용자가 검토안 구현 진행을 승인했다. `history_validation.py`는 정수·유한한 좌표·ID·스키마·옵션·경유지 JSON 규칙과 ImportReport를 담당한다. 가져오기 서비스는 두 파일 전체를 읽고 WGS84·2D 선/점·안내 좌표 일치·배치 중복·경로/안내 연결·안내 건수·기존 ID 충돌을 검사한 뒤에만 저장소의 checked 변경 경로를 호출한다. 오류 메시지에는 파일·레이어·행·이력 ID와 실패 이유가 포함된다.

같은 내용의 파일 내부 중복은 제거하고 기존 동일 이력은 건너뛴다. 같은 ID의 다른 핵심 데이터와 기존의 일부 안내만 있는 상태는 거부하며 자동 덮어쓰지 않는다. 기존 안내가 전혀 없는 동일 경로는 완전한 안내 입력으로 보충할 수 있다. 추가·건너뜀·중복 제거 건수를 완료 메시지와 로그에 표시하고 레거시/손실 경고는 메시지바 요약과 전체 로그로 표시한다.

정상 세 형식의 재불러오기 호환을 확인했다. OGR가 GeoJSON ISO 날짜를 QDate/QDateTime으로 반환하는 사례는 ISO 문자열로 복원한다. 빈 GeoJSON은 CRS와 필드도 없을 수 있으므로 0건 레이어는 좌표/행 검사를 생략한다. 한 부분 MultiLineString은 단일 선으로 정규화하며 여러 부분/3D/다른 geometry는 거부한다. SHP에서 실제 254자 잘림으로 경유지 JSON이 깨지면 경고와 함께 입력 복원 경유지를 비우되, 기존 세션의 긴 JSON을 덮어쓰지 않는다. 지원하는 스키마는 2와 필수 구조를 통과한 레거시 후보이며 실제 버전 1 파일의 완전 호환을 선언하지 않는다.

검증 결과: QGIS 3.44.14·4.2.2 각각 입력 검증, 정상 이력/UI 오류 시 활성 경로 보존, 실패·복구, 내보내기, 런타임 범례/브리지 테스트 통과. 신규 검증은 실제 파일·provider 데이터로 불량 좌표, 미래 스키마, 누락 필수 값, geometry, ID/sequence 충돌, 고아 안내, 연결 route_id·건수 불일치와 데이터/선택 보존을 확인한다. 기존 UI 테스트의 정상 import 오류 대화상자는 assertion으로 바꾸어 자동 테스트가 대기하지 않고 실패하도록 했다. Python 55개·JS 11개 테스트 및 JS 구문 검사, Python 플러그인 소스 17개 컴파일 통과.

배포 파일은 `dist/kakao_qgis_bridge-stage3-import-validation-test.zip`이며 이전 ZIP과 metadata 1.1.1은 유지한다. 실제 사용자 세션/설치 플러그인은 변경하지 않았다. 모델 변경은 GUI 검증 면제 근거가 아니다. 이번 파일 정책의 반복 검사는 자동 검증으로 수행했고, 최종 배포 전 실제 설치 및 카카오 키·지도/로드뷰·동시 외부 연동 화면 확인은 남아 있다.

## 2026-10-07 — 스타일 팩토리 분리 구현

## 2026-10-07 — SHP 손실 안내·GPX XML 문자·빈 파일 문구

사용자 다음 단계 승인 후 구현했다. SHP 내보내기 전에 서비스가 필드별 영향받는 값의 건수를 집계한다. 전체/선택 내보내기 완료 메시지는 손실이 있으면 warning으로 표시하고 완전한 속성 보존을 위한 GeoPackage/GeoJSON을 안내한다. 로그에는 필드명/건수만 남기고 원문은 기록하지 않는다. 선택한 이력만 집계하며 손실이 없으면 기존 성공 안내를 유지한다.

SHP 호환 레이어의 문자열은 기존 필드별 문자 수 제한에 더해 UTF-8 254바이트 상한으로 문자 경계에서 자른다. 한글/이모지의 바이트 중간 잘림을 피하며 원래 이력 레이어는 변경하지 않는다. 이는 SHP 형식 제한 자체를 없애는 변경은 아니며 잘린 경유지 JSON의 기존 가져오기 경고/빈 목록 복원은 유지한다. GPX escaping 단계는 XML 1.0에서 허용하지 않는 문자만 제거하고 한글·이모지·TAB/LF/CR은 유지한다. 빈 파일의 0건 결과와 기존 이력 건너뛰기의 0건 결과는 서로 다른 안내 문구를 사용한다.

순수 writer 규칙 3개 검사가 통과했다. QGIS 3.44.14/4.2.2에서 실제 네 형식 데이터·스타일 출력/재불러오기, SHP 한글과 경유지 JSON 손실 집계/전체·선택 경고/원본 메모리 값 보존, GPX 제어문자 포함 데이터의 유효 XML 및 원본 보존, 빈 파일/재불러오기 안내와 UI 상태 보존, 기존 파일 검증·레거시 SHP/반올림 좌표 호환을 확인했다. 상세 범위는 docs/export-validation.md에 기록했다.
