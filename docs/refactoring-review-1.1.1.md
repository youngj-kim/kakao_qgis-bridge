# 1.1.1 리팩터링 재검토

검토일: 2026-10-07 (Asia/Seoul)

## 결론

1.1.0의 모듈 분리는 유효한 첫 단계다. 다만 플러그인 진입점에서 업무 로직까지 분리하는 작업은 아직 끝나지 않았다. 전면 재작성보다 입력·응답 경계의 안정성 수정, 동기화와 외부 브리지의 상태 모델 정리, 이력·내보내기 책임 분리 순으로 진행하는 것이 적절하다.

줌 동기화, 자동 저장, 인증 관리자 도입, SSE 전환은 기존 동작을 보존하는 리팩터링과 구분해서 별도 변경으로 검증해야 한다.

## 검토 범위와 확인 결과

- 현재 작업 폴더와 `dist/kakao_qgis_bridge-1.1.1.zip`의 27개 배포 파일을 비교했다. CRLF/LF 차이를 제외하면 내용이 동일하다.
- 일반 Python 단위 테스트 10개가 통과했다. 구성은 외부 브리지 5개, Mobility 4개, GPX XML 작성기 1개다.
- `scripts/check_viewer_js.js`의 인라인 JavaScript 구문 검사가 통과했다. 브라우저 동작 검증은 아니다.
- 비객체 응답, 잘못된 거리·시간, 비객체 route/section, 비ASCII 인증 토큰·REST 헤더, 잘못된 회피 옵션 요소에서 예외를 재현했다.
- QGIS를 실제로 실행하거나 Kakao API를 호출하지 않았다. 기존 릴리스 문서에 기록된 QGIS 실행 결과를 이번 검토의 실행 결과로 간주하지 않는다.
- `.github/workflows/ci.yml`에는 일반 Python 검사·Bandit·단위 테스트·JS 구문 검사·ZIP 생성이 있다. QGIS 스모크 테스트 파일도 있지만 현재 CI에서 실행하지 않는다. 원격 CI 성공 여부는 확인하지 않았다.

## 1순위: 낮은 비용의 안정성 수정

### REST 키 검증

대상: `settings.py`, `plugin.py`의 키 입력창, `mobility_client.py:36`.

입력 앞뒤 공백은 기존처럼 제거하되, 내부 공백·개행·비ASCII 입력은 거부한다. 전각 문자를 임의 변환하거나 내부 공백을 지워 다른 키로 바꾸지 않는다. 저장 시 검증뿐 아니라 환경변수·기존 저장값이 들어오는 요청 직전에도 검증한다. 키 전체를 로그나 오류 문구에 포함하지 않는다.

클라이언트는 검증 실패를 `failed` 신호로 전달해 UI가 진행 상태에서 빠져나오게 해야 한다. ASCII 인코딩 예외 처리만으로는 ASCII 개행 같은 잘못된 헤더 입력을 방어하지 못한다.

### 브리지 인증 비교

대상: `external_bridge.py:418`.

`hmac.compare_digest`에 비ASCII 문자열을 넣으면 `TypeError`가 발생한다. 공급 토큰을 ASCII 바이트로 인코딩하고 실패하면 403으로 거부하거나, 양쪽을 UTF-8 바이트로 비교하는 방법이 가능하다. 현재 생성 토큰이 ASCII이므로 ASCII 검증 후 비교가 형식 계약을 가장 분명하게 드러낸다. URL 쿼리와 헤더 경로를 모두 회귀 테스트한다.

한 줄 변경 자체보다 잘못된 입력이 예외 없이 거부되고 정상 세션은 계속 동작하는지가 완료 기준이다.

### 요청·응답 경계 검증

대상: `mobility.py:79`, `mobility.py:281`, `mobility_client.py:94` 이후.

최상위 `payload`뿐 아니라 `routes`, 개별 route, summary, sections, roads의 자료형을 검사한다. 잘못된 거리·시간 변환을 `MobilityResponseError`로 통일한다. 필수 선형 손상은 실패시키고 선택적 안내 항목 손상은 건너뛸지 오류로 처리할지 정책을 정한다.

HTTP 오류 경로도 `payload.get()`을 직접 호출하므로 배열·문자열 JSON에 대한 방어가 필요하다. 401/403/429 메시지를 구분하되 403의 원인을 권한 문제 하나로 단정하지 않는다. 정상 200 응답의 잘못된 JSON은 명확한 응답 형식 오류로 표시한다.

추가로 `avoid_json='[{}]'`는 사전 키 membership 검사에서 `TypeError`를 일으킨다. 요청 옵션의 요소 자료형과 `_json_value` 입력 계약도 같은 변경에서 정리한다.

### 안내 분류

대상: `mobility.py:212`.

[Kakao Mobility 공식 안내 타입 표](https://developers.kakaomobility.com/guide/navi-api/reference.html)를 확인했다. 예를 들어 8/9는 좌우 고속도로 출구, 43/44는 좌우 도시고속도로 출구다. 입출구 코드를 모두 `transition`으로 옮기면 현재 좌우 아이콘 표시가 달라진다.

우선 현재 표시 정책을 명시한 코드→카테고리 매핑을 만들고 알려진 코드는 문구보다 우선한다. 현재는 `guidance_category(2, '왼쪽 차로에서 우회전')`이 `left`로 분류된다. 이것은 우회전 타입을 문구가 덮어쓰는 재현 가능한 문제다.

미분류 코드에서만 문구를 보조로 사용하고, 좌우 단어가 함께 있을 때의 정책을 정한다. 필요하면 다음 단계에서 `maneuver`와 `direction`을 별도 속성으로 분리하되 저장 스키마와 기존 아이콘 호환을 함께 검토한다.

### 진단 문구

대상: `dock_widget.py:61`, `web/kakao_viewer.html` 상태 문구.

WebEngine/WebChannel 가용성에 따라 안내하고, 실제 import 실패 내역은 상세 보기나 로그에 제공한다. 일반 사용자에게는 실행 가능한 대안과 키·도메인 설정 링크를 먼저 보여준다.

Python UI는 Qt 번역을 적용할 수 있지만 HTML 문구에 Python의 `tr()`를 직접 적용할 수는 없다. 먼저 한국어 문구를 일관되게 맞추고, 다국어가 필요할 때 Python 번역 문자열 주입 또는 JS 번역 사전을 설계한다.

## 2순위: 동기화 정확성과 상태 복구

### 타이머 가드 교체

대상: `sync_controller.py:26`, `plugin.py:620`.

600ms 동안 모든 변경을 무시하는 방식은 사용자의 즉시 QGIS 이동까지 누락할 수 있다. 마지막으로 적용한 중심과 현재 캔버스 중심을 비교해 예상한 반영만 억제한다. 비교는 같은 좌표계에서 픽셀 또는 지도 해상도에 따른 허용 오차를 사용하고 CRS 변경 시 기준을 무효화한다.

시간 간격으로 요청을 줄이는 debounce는 유지할 수 있다. 피드백 루프 억제와 요청 빈도 제한은 별개의 책임이다. 내장 뷰어와 여러 외부 탭이 동시에 열리는 경우에는 변경 출처와 revision을 포함해 한 뷰어에서 들어온 이동을 다른 뷰어에도 전달해야 한다. 단순히 마지막 좌표 하나만 저장하면 이 전달 문제는 해결되지 않는다.

### 외부 브리지 스냅샷과 이벤트 복구

대상: `external_bridge.py:25`, `external_bridge.py:292`, `/api/state`, `/api/events`.

현재 중심만 상태로 저장하고 안내·이력·입력 복원은 최근 100개 이벤트에 의존한다. 새 탭은 `since=0`으로 과거 입력 복원까지 재생할 수 있고, 오래 멈춘 탭은 잘린 이벤트를 복구하지 못한다. 이는 전송 기술보다 먼저 수정할 정확성 문제다.

중심·활성 경로·안내·이력·선택 상태를 최신 스냅샷으로 보관하고, 스냅샷과 이벤트 기준 sequence를 같은 잠금 범위에서 얻는다. 클라이언트는 스냅샷 기준 이후 이벤트만 처리한다. 보존 범위보다 오래된 cursor에는 재동기화 필요를 명시하고 스냅샷을 다시 적용한다.

입력 복원처럼 일회성 의도를 가진 명령과, 최신 값으로 복구 가능한 상태 변경을 구분한다. 이벤트 개수 상한은 이미 100개다. 추가로 이벤트 크기와 브라우저→QGIS의 무제한 `Queue`에 대해 제한·중심/Roadview 갱신 병합·과부하 거부 정책을 설계한다.

폴링은 이 단계에서 유지해도 된다. 요청이 겹치지 않게 완료 후 다음 요청을 예약하고 오류 시 지연을 늘리며 POST의 `response.ok`도 검사한다. 현재 POST는 HTTP 실패를 호출 측에 전달하지 않는다.

### 포트와 첫 실행 안내

`KakaoExternalBridgeServer`는 생성자에 포트를 받을 수 있지만 플러그인은 기본 8081로만 생성한다. `KAKAO_MAP_BASE_URL`은 내장 HTML의 기준 URL만 바꾸고 외부 서버 포트를 바꾸지 않는다.

외부 포트 설정과 내장 기준 URL의 관계를 명시하고 실제 사용 출처를 UI에 표시한다. 충돌 시 임의 포트로 자동 전환하면 등록된 Kakao SDK 출처와 어긋날 수 있으므로 설정 변경 및 콘솔 등록을 안내한다.

## 3순위: 책임별 구조 분리

`plugin.py`는 3,453줄, 단일 클래스의 메서드 117개다. `history_export.py`는 45줄의 XML 작성기이고 GPX 데이터 구성·파일 쓰기·QML 생성은 여전히 플러그인에 있다. `HistoryRepository`도 생성·추가 중심이며 검색·삭제·가져오기·스키마 대응은 플러그인에 남아 있다.

분리는 시간 여유가 있을 때만 하는 정리가 아니라 후속 기능의 변경 위험을 낮추는 작업이다. 특히 내보내기 분리는 자동 저장 기능보다 먼저 진행하는 편이 좋다.

| 경계 | 맡길 책임 | 검증 기준 |
| --- | --- | --- |
| HistoryExportService | GPKG/GeoJSON/SHP/GPX 쓰기, 필드 매핑, QML, 내보내기 결과 | 경로·안내 개수, history_id 연결, CRS, SHP 짧은 필드명, 스타일 복원 |
| HistoryRepository 확장 | 검색·선택·삭제·가져오기, 스키마 대응 | 중복 가져오기, 스키마별 복원, 삭제 후 일관성 |
| LayerManager / StyleFactory | 현재 경로·안내·핀·Roadview 레이어와 스타일 수명 | 레이어 수동 삭제, 재생성, 프로젝트 변경, unload |
| ViewerAdapter | WebChannel/HTTP 전송, 공통 상태·명령 계약 | 내장·외부 모드의 동등한 상태 반영 |
| RouteController / HistoryController | 요청 결과 처리, 활성 경로·선택 이력, UI 갱신 조정 | 취소·오류 후 진행 상태 해제, 선택·삭제 후 화면 일관성 |
| plugin.py | QAction, Dock, 객체 조립, 신호 연결, unload | 반복 열기/닫기와 해제 시 중복 연결·잔여 서버 없음 |

새 서비스가 플러그인 객체 전체를 받아 그 private 메서드를 다시 호출하는 형태는 피한다. 필요한 저장소·렌더러·알림 콜백만 전달한다. 현재 `HistoryRepository.append`의 19개 인자도 요청·결과·이력 모델로 묶어 필드 순서 오류를 줄일 수 있다.

먼저 기존 동작을 유지한 책임 이동을 검증하고, 영속화·기능 변경은 다음 변경에서 수행한다. 파일 크기나 줄 수 자체를 완료 기준으로 삼지 않는다.

## 별도 확장으로 진행할 항목

- **줌 동기화:** 기본은 중심 동기화를 유지하고 선택 기능으로 추가한다. 단일 고정 축척표만으로는 CRS·위도·화면 DPI·뷰포트 차이를 설명하기 어렵다. 지역 지상 해상도와 Kakao의 이산 level 사이의 변환·반올림·진동 방지 정책을 검증한다. 줌 변경으로 중심까지 바뀌는 경우도 테스트한다.
- **이력 자동 저장:** 사용자가 저장 위치와 활성 여부를 선택하도록 한다. 저장 실패·잠긴 파일·중복 history_id·스키마 업그레이드·부분 저장을 처리한다. 현재 repository는 경로 추가 성공 후 안내 `addFeatures` 성공 여부를 확인하지 않으므로 일관성 보강이 먼저다.
- **SSE/WebSocket:** 스냅샷 계약 안정화 이후 선택한다. 현재 흐름에는 서버→브라우저 SSE와 기존 POST 조합이 후보지만 재연결 cursor, 서버 종료, 느린 연결, 여러 탭에 대한 검증이 필요하다. 폴링이라는 이유만으로 교체하지 않는다.
- **토큰:** 현재 URL은 브라우저 기록에 남지만 서버 응답은 `no-store`와 `Referrer-Policy: no-referrer`를 이미 설정한다. URL 노출을 줄이는 개선과 즉각적인 대형 취약점을 구분한다. `history.replaceState`는 현재 주소를 정리할 뿐 최초 요청·기록을 완전히 지운다고 보장하지 않는다. 쿠키 전환은 JS 토큰 제거, Origin/CSRF 정책, 쿠키 Path·포트 간 공유·복수 인스턴스까지 포함한 인증 설계 변경이다.
- **REST 키 인증 관리자 저장:** `QgsAuthManager` 연동 시 마스터 비밀번호와 환경변수 우선순위, 평문 저장값 이전 성공·실패를 설계한다. 확인된 이전 완료 전에는 기존 값을 지우지 않는다. 레거시 `settings.json`은 JavaScript 키용이므로 REST 키 개선에 묶어 자동 삭제하지 않는다.
- **약관·쿼터:** 이번 검토에서 승인 여부를 확인하지 않았다. 배포 구성과 사용 범위에 대한 별도 확인 항목이며 코드 구조 분리의 완료 기준과 구분한다.

## 권장 변경 단위와 완료 기준

1. 안정성 패치: 키·인증·요청/응답 검증·안내 타입 우선순위·진단 문구. 재현된 잘못된 입력이 표준 실패 경로로 처리되어야 한다.
2. 동기화/브리지 수정: 즉시 사용자 이동 보존, 다중 뷰어 반영, 새 탭·재연결 스냅샷 복구, 포트 안내. 임의 시간 대기 대신 상태를 검증한다.
3. 내보내기/이력/레이어 책임 분리: 기존 파일 형식과 필드·스타일을 보존하고 불러오기까지 확인한다. 일반 Python 테스트 외에 QGIS 실행 검증이 필요하다.
4. 선택 확장: 줌 동기화·자동 저장·인증 관리자·전송 방식 변경을 각각 독립적으로 검증한다.

검토 문서만 추가했으며 실행 코드와 배포 ZIP은 변경하지 않았다.
