# 경로 입력 컨트롤러 및 1.2.1 배포 후보

## 구현

viewer_route_input.js가 출발/도착 입력, 옵션, 최대 5개 경유지 편집·순서 변경,
이력 입력 복원, SDK 위치 변환과 브리지 경로 요청, busy 상태를 담당한다.
DOM 노드, map/bridge/service getter와 검색·표시·타이머 콜백을 명시적으로 받는다.
외부 브리지 및 WebChannel 함수명과 데이터 형식은 유지한다.

프로젝트 reset/입력 clear/이력 복원 시 요청 세대를 올린다. 이전 위치 변환이
성공하거나 실패해도 새 입력·busy·상태 메시지·경로 요청을 변경하지 않는다.
중복 요청을 억제하고 위치 변환/동기 브리지 전달 오류에서는 busy를 해제한다.
SDK 반환 좌표의 유한값 및 범위를 확인하고 주소 우선, 장소 대체 순서를 유지한다.

## 검증

Python 62개, JavaScript 37개(경로 입력 신규 9개), 제품 JS 구문과 Python
컴파일을 검증했다. QGIS 3.44.14/4.2.2에서 두 HTML 조립 경로, 브리지 런타임,
프로젝트 전환, 이력, 네 형식 내보내기 회귀가 통과했다.
Bandit 1.9.4로 제품 Python 전체를 검사해 발견 항목 및 제외 파일/규칙 0건이었다.
Bandit은 루트 .qa-tools/bandit에만 설치했으며 시스템 Python/QGIS는 변경하지 않았다.

검사는 fixture 기반이며 실제 Kakao SDK/사용자 API 키를 사용하지 않는다.
비동기 브리지의 HTTP 오류는 기존 routeStatusChanged 경로에서 처리한다.
응답 없는 SDK 위치 변환의 시간 제한이나 외부 브리지 프로토콜 재설계는 범위 밖이다.

## 지도·로드뷰 초기화/레이아웃 검토

남은 메인 JavaScript는 SDK 준비와 지도·로드뷰 동기화, relayout/timer,
브리지 시그널 조립을 담당한다. 이 상태들은 움직임 echo 억제와 늦은 panorama
응답 차단, WebEngine resize 안정화에 공동으로 사용된다.
추가 분리는 선택적 개선이며 현재 회귀 위험에 비해 이득이 작아 이번에는 유지한다.
이 판단을 기능 미완료나 SDK 전체 분리 완료로 표현하지 않는다.

## 배포

누적 이력 UI·내보내기 UI·Viewer 모듈 변경을 1.2.1 후보로 구분했다.
metadata/README/CHANGELOG를 갱신하고 기존 1.2.0 ZIP은 보존한다.
후보 ZIP은 dist/kakao_qgis_bridge-1.2.1.zip이다.
45개 제품 파일의 ZIP 무결성·루트 바이트 일치·체크아웃 텍스트 일치,
설정/캐시 제외와 기존 최종 ZIP 보존을 확인했다.
실제 설치 화면 검증 전에는 최종 승인된 배포라고 표시하지 않는다.
GitHub 소스 반영은 release/tag 생성 및 공식 QGIS 저장소 업로드와 구별한다.

남은 사용자 확인: 최신 ZIP으로 QGIS 3·4에서 검색, 출발/도착·경유지 편집,
경로 요청·안내 선택, 이력 복원/삭제, GPKG/GeoJSON/SHP/GPX 내보내기,
프로젝트 전환 후 재요청을 확인한다. 선언된 QGIS 3.34 실행 검증과 약관·쿼터
검토도 별도이며 현재 자동 검사로 완료를 주장하지 않는다.
