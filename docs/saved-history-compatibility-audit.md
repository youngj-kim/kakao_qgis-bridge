# 기존 저장 이력 호환성 재검토

검토·수정일: 2026-10-07. 사용자가 QGIS 3·4의 기존 GPKG/GeoJSON/SHP 불러오기 오류를 보고했다. 직전 입력 검증이 자체 저장 형식의 실제 표현을 충분히 반영하지 못한 회귀 문제였다.

## 확인한 문제와 처리

| 항목 | 실제 기존 데이터 | 수정 |
| --- | --- | --- |
| 안내 좌표 | 점 geometry는 정밀 좌표, 경도·위도 속성은 소수점 5자리 | 두 속성이 geometry를 5자리로 반올림한 값과 일치할 때만 경고 후 geometry 좌표로 메모리 속성 복원. 임의의 가까운 좌표 불일치는 거부 |
| 도로 인덱스 | 경유지·도착 안내에 `road_index=-1` 존재 | -1을 유지. 거리·시간·건수의 음수 금지와 sequence 양수 규칙은 유지 |
| 예전 안내 SHP | history_id/schema 필드 없음. route_id·sequence 존재 | 짝 경로 파일의 비어 있지 않은 route_id가 정확히 한 이력에 연결될 때만 history_id 복원. 없는 연결/여러 이력에 같은 route_id는 거부. 누락된 필수 ID를 일반적으로 추정하지 않음 |
| 예전 SHP 필드명 | `cum_distan`, `cum_durati` | 위 레거시 안내 형식에서 누적 거리·시간 필드로 매핑하여 값 유지 |
| 기존 세션과 재불러오기 | 같은 경로의 요청 좌표도 5자리 반올림 가능 | geometry·경로 ID·거리/시간 등 핵심 확인을 유지하면서 요청 좌표의 명확한 5자리 반올림 표현 차이는 동일 이력으로 인정. 기존 정밀 좌표는 덮어쓰지 않음 |
| 새 파일 저장 | 정밀도를 생략한 double 필드 사용 | 이력 저장소와 SHP 호환 레이어의 좌표를 `double(20,10)`으로 지정. GeoJSON geometry 출력은 기존 8자리 유지. 새 출력의 좌표/geometry가 기존 1e-7 기준을 통과하는지 확인 |

SHP의 이름·설명·JSON 문자열 잘림은 형식 제한이다. 깨진 SHP 경유지 JSON은 경고와 함께 입력 복원용 목록을 비우며, 기존 세션의 완전한 값은 유지한다. 읽힌 빈 선택 문자열이 NULL로 표시되는 경우는 알려진 기본값으로 복원한다. 필수 좌표·ID·연결·건수 손상과 여러 부분 geometry는 계속 거부한다.

## 실제 파일 검증

`tests/qgis_saved_history_audit.py`로 Desktop에 있는 카카오 이력 파일 11개(경로/안내 짝을 한 건으로 계산)를 읽었다: GPKG 4개, GeoJSON 5개, SHP 2개. QGIS 3.44.14와 4.2.2 각각 모두 통과했다. 첫 실행에서는 오래된 SHP 하나가 history_id 누락으로 실패했고 위의 제한적 route_id 연결 처리 후 통과했다.

각 파일에 대해 최초 import, 같은 파일 재import 중복 방지, 세 형식으로 임시 저장 후 빈 세션 복원, 기존 세션 중복 병합을 확인했다. 새 저장 데이터에는 안내 좌표 5자리 복원 경고가 발생하지 않아 저장 정밀도 개선을 확인했다. SHP의 .shp/.shx/.dbf/.prj/.cpg와 GeoJSON 짝 파일, GPKG의 SHA-256을 전후 비교하여 원본 내용이 그대로임을 확인했다. 테스트 저장은 임시 폴더와 임시 메모리 저장소에만 수행했다.

`tests/qgis_history_validation.py`에는 5자리 반올림/임의 좌표 차이 구분, road_index -1, 반올림된 요청 좌표와 정밀 세션 간 중복, 실제 예전 SHP 필드 생성·값 복원, 모호한 route_id 거부 사례를 추가했다. 정상 이력/UI 오류 보존, 네 형식 내보내기와 기존 변경 실패·복구 테스트도 양쪽 QGIS에서 통과했다. 순수 값 규칙 단위 테스트 6개 통과.

수정 패키지: `dist/kakao_qgis_bridge-stage3-import-compatibility-test.zip`. 앞서 제공한 import-validation ZIP에는 이 호환 수정이 없으므로 새 패키지를 설치해야 한다. 기존 ZIP, 원본 저장 파일, 실행 중인 사용자 QGIS의 플러그인은 자동으로 교체하지 않았다. 실제 설치 후 사용자 UI 확인은 자동 검증과 구분한다.
