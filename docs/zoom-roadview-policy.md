# 확대·축소와 로드뷰 이동 분리 — 2026-10-12

> 최신 동작: 아래 초기 단계 이후 사용자의 요청으로 **양방향 줌 연동**을 추가했다.
> QGIS↔카카오지도는 이동과 확대·축소를 모두 전달한다. 줌만 할 때는 로드뷰 촬영 지점을 유지한다.
> 아래의 축척 비동기화 설명은 이전 단계 기록이다.

## 동작

- QGIS 캔버스 해상도가 바뀌는 확대·축소는 지도 중심만 카카오맵에 전달한다. 로드뷰 촬영 지점과 위치 마커는 유지한다.
- 같은 해상도에서 중심이 바뀌는 지도 이동은 기존처럼 로드뷰를 갱신한다. 연속 줌 이후의 드래그도 포함한다.
- 로드뷰 안의 이동 화살표는 기존처럼 QGIS를 해당 위치로 이동시킨다.
- QGIS의 마우스 휠 기준점, 카카오맵 확대 단계, 두 지도 간 축척 동기화는 변경하지 않는다.

## 구현과 검증

CanvasSyncController가 이전 중심·CRS·지도 단위/픽셀을 비교해 갱신 종류를 구분한다.
크기 변경이나 프로그램에 의한 범위 맞춤처럼 해상도가 바뀌는 동작도 지도 확대·축소로 취급한다.
프로젝트 초기화와 CRS 변경 시 판단 상태를 초기화한다.
도킹 화면과 외부 브라우저에는 update_roadview를 전달하며, 기존의 인자 없는 호출은 위치 이동으로 처리한다.
API 준비 전 최초 화면은 초기 촬영 위치를 한 번 설정한다. 이후 줌에서는 기존 촬영 위치를 유지한다.
줌 전에 시작된 비동기 파노라마 조회는 줌 이후 결과가 도착해도 적용하지 않는다.

회귀 검사는 줌/팬 구분, 연속 줌 및 중복 신호, 줌 후 팬 재개, CRS/초기화,
웹 지도만 이동, 기존 파노라마/마커 유지, 오래된 조회 무시, 외부 상태 복원과 실시간 이벤트 전달을 포함한다.
실제 Kakao SDK 화면에서 QGIS 3/4의 휠 줌 → 드래그 → 로드뷰 화살표 순서로 최종 수동 확인이 필요하다.

자동 검증: Python 66개, JavaScript 40개, inline 스크립트 구문 검사와 Bandit 검사 통과.
QGIS 3.44.14/4.2.2 실제 캔버스·브리지 검사 및 앞선 경로 핀 회귀 검사 통과.

테스트 ZIP은 앞선 경로 핀 위치 수정도 포함한다. 기존 배포 ZIP은 보존하며 커밋/푸시는 별도 요청 후 진행한다.

## 플러그인 지도 자체의 휠 줌 보강

사용자가 플러그인 카카오지도 위의 휠 입력으로 지도 자체가 확대·축소되지 않는다고 확인했다.
소스에서 명시적 휠 차단은 발견하지 못했으므로 Qt/SDK 환경의 근본 원인까지 확정하지는 않는다.
지도 컨테이너에 SDK 생성 전 capture/non-passive wheel 처리를 등록하여 지도 확대 단계를 직접 변경한다.
같은 이벤트가 SDK에서 중복 처리되지 않게 막고, 마우스 위치의 지도 좌표를 anchor로 사용한다.
작은 트랙패드 입력을 누적하고, 픽셀/줄/페이지 단위를 반영하며 기본 일반지도 확대 단계 1~14를 지킨다.
휠 처리 범위는 지도에 한정되며 검색 입력창과 로드뷰의 스크롤 동작은 건드리지 않는다.
SDK 휠/터치 확대 설정은 활성화하고, 표준 확대·축소 컨트롤도 추가한다.
이 동작은 로드뷰 조회, 위치 마커 변경, QGIS 이동이나 축척 변경을 요청하지 않는다.

최신 JavaScript 42개 검사와 inline 스크립트 구문 검사를 통과했다.
자동 검사에는 직접 휠 처리, 기준점, 중복 방지, 트랙패드/단위/범위 및 로드뷰 비간섭 검사가 포함된다.
실제 QGIS 내 휠 이벤트 전달과 Kakao SDK 화면 동작은 재설치 후 수동 검증이 필요하다.

## 양방향 줌 연동

- QGIS는 프로젝트 CRS에서 수평 128픽셀 구간을 WGS84로 변환해 실제 지상 거리/픽셀을 계산한다.
- 카카오는 SDK MapProjection으로 화면 중앙 128픽셀 구간의 실제 지상 거리/픽셀을 계산한다.
- 동일한 구면 거리식을 양쪽에 사용하며, 카카오 확대 단계가 이산적이므로 QGIS 값에 가장 가까운 단계로 맞춘다. 모든 임의 축척의 완전한 일치를 보장하지 않는다.
- QGIS의 중심/확대 비율은 도킹 화면과 외부 브라우저로 전달한다. 카카오 zoom_changed는 최종 중심/확대 비율을 전용 Qt 슬롯 또는 인증된 localhost API로 QGIS에 전달한다.
- 카카오에서 받은 확대를 적용할 때 QGIS 축척 잠금은 존중한다. 카카오 일반지도 확대 단계 1~14 밖의 QGIS 축척은 일치시킬 수 없다.
- 같은 중심의 확대도 처리하도록 QGIS 반향 차단 조건에 해상도를 추가했다. 카카오의 프로그램 줌은 기대 단계로 반향을 차단하고 대기 중인 줌 이벤트를 취소한다.
- 지도 이동은 기존 중심 동기화와 로드뷰 재조회를 유지한다. 줌 이벤트는 로드뷰 재조회나 촬영 위치 마커 이동을 요청하지 않는다.
- 프로젝트 초기화는 대기 중인 줌 타이머와 기대 단계를 초기화한다. 잘못된 확대 비율은 캔버스 변경 전에 거부한다.

실제 SDK 화면에서 양방향 휠/버튼 줌, 양쪽 지도 드래그, 로드뷰 화살표 이동을 최종 확인해야 한다.

최신 검증: Python 69개, JavaScript 45개, Bandit 및 inline 스크립트 검사 통과.
QGIS 3.44.14/4.2.2에서 도크 Qt 줌 슬롯, QGIS 동일 중심 줌, 줌 후 팬, 외부 브라우저 이벤트,
반향 차단, 잘못된 값 거부 및 EPSG:4326 프로젝트의 실제 캔버스 검사를 통과했다.
기존 QGIS 런타임 페이지 조립·브리지·이력·위치 동기화 검사도 양쪽 버전에서 통과했다.
