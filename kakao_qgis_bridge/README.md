# Kakao QGIS Bridge 1.2.2

상단 탐색창 접기 / 펼치기로 검색·지도 설정·경로 입력·안내/이력 영역 전체를 숨기거나
다시 엽니다. 입력값과 탐색 결과는 유지하고 지도·로드뷰 표시 공간을 넓힙니다.

첫 도크 분리 시 화면 가용 영역 안에서 1100×850 논리 픽셀 기준으로 크기를 넓힙니다.
이후 사용자 조절 크기를 강제로 초기화하지 않습니다. 지도·로드뷰는 탐색창을 제외한 남은 높이를 나눠 씁니다.

장소·주소 검색 후 검색 결과 N개 접기 / 펼치기 버튼으로 결과 목록을 숨기거나 다시 엽니다.
접어도 검색 결과는 유지되고, 새 검색은 목록을 자동으로 펼칩니다.

검색창 아래 지도 선택에서 일반지도 / 항공영상 / 항공영상+지명을 전환할 수 있습니다.
로드뷰 도로 표시 버튼은 촬영 도로 선을 켜고 끕니다. QGIS 배경지도는 바꾸지 않으며
전환 자체는 로드뷰 촬영 위치를 이동하지 않습니다. 촬영 도로 선은 촬영일을 제공하지 않습니다.

Kakao Map·Roadview와 QGIS의 위치·확대 수준을 연동하는 플러그인이다. 실행 환경에 따라 도킹 뷰어 또는 외부 브라우저를 사용한다.

## 설치와 키 설정

1. QGIS 플러그인 관리자에서 배포 ZIP을 설치하고 QGIS를 다시 시작한다.
2. Kakao Developers의 앱에서 JavaScript 키와 REST API 키를 확인한다.
3. JavaScript 키의 JavaScript SDK 도메인에 아래 두 출처를 등록한다.

   - `http://localhost:8081`
   - `http://localhost:8082`

4. `Kakao Map / Roadview`를 열어 JavaScript 키를 입력한다. 최초 경로 생성 시 REST API 키를 입력한다. 변경은 플러그인의 각 API 키 설정 메뉴에서 한다.

JavaScript 키는 지도·로드뷰·장소 검색, REST API 키는 Mobility 경로 탐색에 사용한다. 키에는 공백이나 전각 문자를 넣지 않는다. 키 입력값은 QGIS 사용자 설정에 저장되며 암호화되지 않는다. 실제 키를 소스나 배포 파일에 넣지 않는다.

공식 도메인 설정 안내: https://apis.map.kakao.com/web/guide/

## 두 도메인을 등록하는 이유

8081은 외부 브리지의 기본 포트이고, 8082는 8081을 다른 QGIS나 프로그램이 사용할 때 선택하는 대체 포트다. QGIS 3·4의 외부 연동을 동시에 열 때도 각각 다른 포트를 사용할 수 있다.

포트가 다르면 SDK가 판단하는 출처도 다르다. 8081만 등록하면 8082로 전환될 때 지도가 로드되지 않을 수 있으므로 두 주소를 같은 JavaScript 키에 등록한다. 새 키 발급은 필요 없다. 두 포트가 모두 사용 중이면 주소 등록과 별개로 플러그인이 연결 오류를 안내한다.

## 외부 브라우저와 동시 실행

WebEngine/WebChannel을 사용할 수 없으면 외부 브라우저 연동을 사용한다. 내장 뷰어에서도 외부 창을 열 수 있다. 플러그인 버튼으로 새 창을 연다. 외부 서버는 8081을 먼저 사용하고 사용 중이면 8082를 사용한다. 두 포트가 모두 사용 중이면 오류를 안내한다. QGIS 3·4를 동시에 사용할 때도 두 도메인을 등록한다.

오래된 탭은 이전 세션 토큰 때문에 403이 날 수 있다. 현재 QGIS의 버튼으로 다시 연다. 주소를 직접 입력하면 인증되지 않는다. 도메인 미등록에 따른 SDK 오류와 로컬 브리지의 403은 원인이 다르다.

`KAKAO_MAP_BASE_URL`은 내장 WebEngine의 기준 URL 설정이며 외부 서버 포트를 바꾸지 않는다. 내장 기준 URL을 바꾼 경우 그 출처도 SDK 도메인에 등록한다.

## 지원 환경과 제한

- `GPKG 경로 비교...` 메뉴에서 카카오·네이버 경로 파일을 A/B로 열어 거리·예측 소요 시간·조회 시점과 출발/도착/경유지 차이를 비교한다. A는 파랑 실선, B는 주황 점선으로 표시한다. 원본 파일과 세션 이력을 변경하지 않는다. EPSG:4326의 `kakao_route_history` 또는 `naver_route_history` 레이어가 필요하다.
- 지원 대상: QGIS 3.34 이상(3.34는 미검증)과 QGIS 4 / Qt 6. 실행 확인 환경은 Windows QGIS 3.44.14 / 4.2.2다.
- QGIS↔Kakao Map의 이동·확대·축소를 양방향 연동한다. 줌만 할 때는 Roadview 촬영 위치와 위치 마커를 유지하며, 지도 드래그와 Roadview 내부 이동 시에는 위치도 따라간다.
- 카카오의 가장 가까운 이산 확대 단계로 맞추므로 임의 QGIS 축척과 완전히 일치하지 않을 수 있다. 일반지도 단계 1~14 범위와 QGIS 축척 잠금을 따른다.
- 경로 결과 핀은 API 안내 위치를 표시하며 원래 입력 좌표는 보존한다. 현재 안내 레이어의 작은 출발·도착·경유 핀만 숨기고 큰 Route Points 핀과 회전·유턴 안내는 유지한다.
- 경로 결과에 경유지 안내가 없으면 해당 경유지 결과 핀은 표시하지 않는다. 원래 입력 좌표는 보존한다.
- 경로 이력은 메모리에서 관리한다. 종료 전에 GeoPackage 또는 GeoJSON으로 저장한다. 자동 저장은 지원하지 않는다.
- 프로젝트 전환 시 현재 표시·입력·이전 요청은 초기화하지만 세션 이력은 유지한다. 이력 탭에서 선택하면 새 프로젝트에 다시 표시할 수 있다.
- SHP는 긴 문자열·경유지 JSON을 잘라낼 수 있으며 손실이 있으면 경고한다. 완전한 속성 보존은 GeoPackage/GeoJSON을 사용한다.
- GPKG 경로 비교는 EPSG:4326의 `LineString`/`MultiLineString` 레이어를 지원한다. 일반 `Geometry` 선언 레이어는 지원하지 않는다.
- 새 경로 이력은 통행료·예상 택시요금을 저장하며 GPKG 비교표에 A/B 금액과 차액(B−A)을 표시한다. 요금 없는 기존 파일은 ‘정보 없음’으로 표시한다. 새 요금은 다시 경로를 조회하고 내보내야 저장되며 기존 파일에서 복원하거나 추정하지 않는다. 예상 택시요금과 통행료를 합산하지 않으며 실제 청구액을 보장하지 않는다.
- 외부 브라우저 토큰은 URL에 포함된다. REST 키의 인증 관리자 저장은 후속 개선 사항이다.
- SDK 임베드의 약관·쿼터 적합성은 별도 확인 대상이다.
